# 团队培训安排

登记成员、创建带容量的培训活动，记录报名、批量取消报名、改报与查看参与名单，并登记与查询培训完成记录。

## 运行

需要 Python 3.10 或更新版本，仅使用标准库，无依赖安装步骤。请在本目录运行：

```sh
python3 -m team_planner --root ./state demo
python3 -m unittest discover -s tests -v
```

这是本地命令行程序，不监听网络端口，无账户或密码。`demo` 在指定 root 的临时子目录中读取 examples 样例并演示业务，结束后清理样例状态，不改变现有数据。

## 正常使用

公开 API：`from team_planner import TeamPlanner`，然后 `TeamPlanner(root)`。每个命令接收可选的 JSON 文件，其对象键与 API 方法参数一致。例如：

```sh
python3 -m team_planner --root ./state member examples/members.json
```

JSON 数组会按顺序执行多个独立操作；先前成功操作保留，后续失败不会回滚整批。重跑登记命令遇到已存在的标识会报错。

- `member` → `TeamPlanner.add_member(...)`。参数名见 `core.py` 的公开方法签名。
- `activity` → `TeamPlanner.create_activity(...)`。参数名见 `core.py` 的公开方法签名。
- `enroll` → `TeamPlanner.enroll(...)`。参数名见 `core.py` 的公开方法签名。
- `cancel` → `TeamPlanner.cancel_enrollments(...)`。输入对象包含 `member_id`、`activity_ids`；成员标识与每个活动标识去除首尾空白后须为非空字符串，`activity_ids` 必须是非空数组且去空白后无重复。一次调用撤回该成员在全部指定活动中的席位，只有成员存在、每个活动存在、成员在每个活动中均已报名，且在任一活动都没有本人完成记录时才整体生效：其他成员的完成记录不阻止取消，本人在未选中活动的完成记录也不影响操作。各活动只移除该成员，其余参与者相对顺序以及标题、日期、容量均不变，完成记录全部保留；释放的席位可立即继续报名或改报。成功返回更新后的完整活动对象数组（字段与 `activity`、`enroll` 一致），顺序与输入活动顺序一致。任一条件不满足均抛出 `ValueError` 且原有数据文件内容不变；此前没有数据目录或 `data.json` 时取消失败也不会创建。取消不依赖当前日期，过去但尚未登记完成的报名同样可撤回。
- `transfer` → `TeamPlanner.transfer_enrollment(...)`。输入对象包含 `source_activity_id`、`target_activity_id`、`member_id`，三个标识去除首尾空白后须为非空字符串。把该成员的一次报名从原活动转到目标活动：从原活动名单移除（其余成员相对顺序不变）并追加到目标活动名单末尾，原活动释放一个名额、目标活动占用一个名额，成功返回目标活动完整对象（字段与 `activity`、`enroll` 一致）。任一活动或成员不存在、两项活动相同、成员未报名原活动或已报名目标活动、目标活动已满都会被拒绝。成员在原活动已有本人完成记录时拒绝改报（其他成员的完成记录不阻止操作，任何完成记录都不会被删除或迁移）；成员在目标日期已报名第三个活动时拒绝，检查排除原活动与目标活动，已完成培训的报名同样算冲突。成员档案及两项活动的标题、日期、容量均不变。
- `reschedule` → `TeamPlanner.reschedule_activity(...)`。输入对象包含 `activity_id`、`on`；新日期须为真实存在的 `YYYY-MM-DD` 字符串。成功返回完整活动对象（仅 `on` 改变，标题、容量、参与者及顺序不变）。新日期与原日期相同时直接返回原活动，不重写数据。活动已有任何完成记录，或某位当前参与者已报名新日期当天的另一活动时拒绝调整。
- `reschedule-batch` → `TeamPlanner.reschedule_activities(...)`。输入对象包含 `changes`；`changes` 必须是非空数组，每项只含 `activity_id` 与 `on` 两个字段，标识去除首尾空白后须为非空字符串、规范化后不得重复，活动须存在，日期只接受无首尾空白、真实存在的 `YYYY-MM-DD` 字符串。整组调整一起生效：冲突按全部活动调整后的最终日期判断，可行的互换不会因中间状态被拒绝。仅日期实际改变的活动受约束——其任一参与者在最终日期已报名另一场活动（无论是否在本组内、是否已完成）即拒绝整组，只有其他成员报名不算冲突；实际改期的活动存在任何完成记录时拒绝。日期不变的条目允许保留完成记录或原有冲突，全组日期都不变时返回原活动且不重写文件，无关的历史冲突不阻止操作。成功返回完整活动对象数组（字段与 `reschedule` 结果一致），顺序与输入一致，仅各所选活动的 `on` 改变，成员档案、标题、容量、参与者顺序与完成记录均保留。任一条件不满足均抛出 `ValueError`，整次失败保持数据文件字节不变，此前没有目录或 `data.json` 时也不创建。顶层 JSON 数组表示多个独立批次，先前成功的批次保留，遇错停止且标准输出为空。
- `roster` → `TeamPlanner.roster(...)`。参数名见 `core.py` 的公开方法签名。
- `list` → `TeamPlanner.activities(...)`。参数名见 `core.py` 的公开方法签名。
- `complete` → `TeamPlanner.record_completion(...)`。输入对象包含 `activity_id`、`member_id`、`completed_on`；完成日期须为真实存在的 `YYYY-MM-DD` 日期，且不早于活动日期。成功返回单条完成记录（含活动的 `title`、`on`）。
- `complete-batch` → `TeamPlanner.record_completions(...)`。输入对象包含非空 `records` 数组，每项只含 `activity_id`、`member_id`、`completed_on` 三个字段，允许跨活动、跨成员提交。活动与成员标识去除首尾空白后须为非空字符串；完成日期只接受无首尾空白、真实存在的 `YYYY-MM-DD` 字符串，不早于对应活动日期，不受当前日期限制。整组一起生效：每条记录的活动和成员均须存在、成员已报名该活动且没有该活动的本人完成记录；去空白后重复的活动与成员组合整组拒绝（日期相同也不合并），其他成员的完成记录不阻止登记。成功返回记录数组，字段与 `complete` 的结果相同，顺序与输入一致；只增加所选完成记录，既有完成记录、成员档案、活动字段、参与者顺序与额外字段均保留，报名继续占用容量。`records` 类型错误或为空、条目不是对象、缺少或多出字段、标识类型错误或为空、日期无效，以及任一业务条件不满足时均抛出 `ValueError`，整组不新增记录，已有 `data.json` 字节不变，此前没有数据目录或 `data.json` 时也不创建。随后 `completions`、`schedule`、`export-schedule` 按既有规则显示和筛选新记录，取消、改报、改期、合并继续遵守已有约束；历史文件缺少完成记录字段时按无记录处理。顶层 JSON 数组表示多个独立批次，先前成功批次保留，遇错停止且标准输出为空。
- `completions` → `TeamPlanner.completions(...)`。输入对象包含 `member_id`；返回该成员的完成记录数组，按 `completed_on`、`on`、`activity_id` 升序排列，无记录时为空数组。
- `schedule` → `TeamPlanner.member_schedule(...)`。输入对象包含 `member_id` 及可选 `from_on`、`to_on`、`status`。成员标识去除首尾空白，非字符串、空白或未知成员都会被拒绝。日期省略或为 `null` 时不限制对应边界，否则须为真实存在的 `YYYY-MM-DD`，范围包含两端并按活动日期筛选，起日晚于止日会被拒绝。`status` 默认为 `all`，只接受 `all`、`pending`、`completed`：后两者分别表示没有本人完成记录和已有本人完成记录，不随当前日期变化。结果只收录该成员已报名的活动，每项含 `activity_id`、`title`、`on`、`status`、`completed_on`、`conflict_activity_ids`；未完成时 `completed_on` 为 `null`。结果按 `on`、`activity_id` 升序排列，无匹配时为空数组。`conflict_activity_ids` 为该成员同日已报名的其他活动标识（去重、升序、排除自身），仅其他成员报名的活动不计入；同日已完成或被状态筛选隐藏的报名仍算冲突。查询不修改数据文件，空目录查询未知成员也不创建目录或文件。
- `export-schedule` → `TeamPlanner.export_schedule(...)`。输入对象包含可选 `from_on`、`to_on`、`status`，含义与校验规则和 `schedule` 完全一致（日期省略或为 `null` 不限边界、范围含两端、起日晚于止日或非法 `status` 均抛出 `ValueError`，`status` 默认 `all`）。导出全员培训日程：每条现有报名占一行，未报名成员与无人报名的活动不产生行，已取消的报名不出现，已完成的报名仍保留。返回含 `csv` 字符串与 `row_count` 整数的对象，`row_count` 只统计数据行。表头固定为 `member_id,name,activity_id,title,on,status,completed_on,conflict_activity_ids`，数据行按 `on`、`activity_id`、`member_id` 升序排列，姓名与标题取当前档案，未完成的 `completed_on` 单元格为空。`conflict_activity_ids` 为紧凑 JSON 数组，列出本人同日其他已报名活动标识（去重、升序、排除本场；已完成或被状态筛选隐藏的报名仍计入，其他成员的报名不计入）。CSV 以逗号分隔，含逗号、双引号或换行的单元格加双引号且内部双引号写成两个，中文与原有换行无损保留，行结束符统一为 CRLF，不添加 BOM。没有匹配记录时仍返回表头且 `row_count` 为 0。导出只读取数据，不改写 `data.json`，也不创建缺失的目录或文件；缺少完成记录字段的历史文件按全部未完成处理。命令只把该对象以 JSON 打印到标准输出，不生成导出文件。
- `merge` → `TeamPlanner.merge_member(...)`。输入对象包含 `source_member_id`、`target_member_id`，分别为被合并成员与保留成员；标识去除首尾空白，非字符串、为空、两者相同或任一成员不存在都会被拒绝。被合并成员在各活动中的席位并入保留成员：仅其报名时在原位置替换为保留成员，两人都报名时保留一个位于两人中较早位置的席位，其余成员相对顺序不变，去重释放的名额可继续报名。完成记录仅一人有则归入保留成员；两人在同一活动都有记录时 `completed_on` 相同才合为一条，不同则拒绝整个合并（不选择日期、不覆盖记录）。成功返回保留成员对象并删除被合并成员档案。

登记完成不取消报名、不释放名额，也不改变名单顺序；同一成员在同一活动只能登记一次。活动或成员不存在、成员未报名、重复登记或完成日期早于活动日期都会被拒绝。历史 `data.json` 没有完成记录字段时视为没有已完成培训。合并同样不额外拒绝同日多项报名；任何活动上的完成日期冲突都会拒绝整个合并，不留下部分结果，失败也不创建数据文件。改报在任一条件不满足时同样不修改两边名单及其他数据，失败前没有 `data.json` 也不会创建。

命令成功向标准输出打印 JSON 并返回 0；输入或本地文件错误向标准错误输出说明并返回 2。无参数的方法可省略输入文件。数据保存在 `root/data.json`，每次成功修改后保存；适用于单进程本地使用。

## 历史数据一致性

所有读取 `root/data.json` 的 API 与命令采用同一套校验标准。文件不存在时按空数据处理；文件存在时每次读取都校验**整份**数据，因此任何查询筛选都不会掩盖其他非法记录。数据有效时结果与以往一致；任一处无效时本次调用直接被拒绝（抛出 `ValueError`），不返回部分结果，已有文件字节不变，也不会因失败创建缺失的目录或文件。文件不是有效 UTF-8、不是有效 JSON、或顶层不是 JSON 对象同样抛出 `ValueError`；读取文件本身的操作系统错误（权限、`data.json` 是目录等）仍抛出 `OSError`。

- 顶层必须是 JSON 对象。缺少 `members`、`activities`、`completions` 任一字段时，该字段视为空集合；字段存在时必须是 JSON 对象，`null` 不算空对象。顶层允许有额外字段。
- 成员条目必须是对象：须有与外层键完全一致的 `member_id`，`name` 为非空白字符串，允许额外字段。
- 活动条目必须是对象：须有与外层键完全一致的 `activity_id`，`title` 为非空白字符串，`on` 为无首尾空白、真实存在的 `YYYY-MM-DD`，`capacity` 为非布尔的正整数（`true` 不算 1），`participants` 为数组，允许额外字段。
- 集合的外层键以及 `participants` 中的成员标识必须是无首尾空白的非空字符串。
- 参与者只能引用已存在的成员，不得有重复标识，人数不得超过容量；同一成员同日报名多项活动仍然合法。
- 完成记录的外层键必须引用已存在的活动；其值为对象，以该活动**已报名成员**标识为键、以真实 `YYYY-MM-DD` 完成日期为值，完成日期不得早于活动日期；空内层对象允许保留。
- 合法历史数据继续兼容：缺少 `completions` 字段表示没有完成记录，已完成报名继续占位；顶层、成员和活动对象上的额外字段在成功修改后原样保留，程序不会顺手修补旧文件。

命令遇到上述校验错误时标准输出为空，标准错误输出含 `error` 的 JSON 并返回 2；成功输出、`demo` 以及顶层输入数组逐项执行并保留此前成功操作的语义不变。

## 样例

`examples/` 提供 3 份虚构业务样例。`tests/` 覆盖业务路径、拒绝非法操作后的状态和命令入口。

## 当前边界

当前只管理培训报名、取消报名与完成登记，不支持请假、排班、候补或权限系统。 不承诺并发写入或断电恢复。
